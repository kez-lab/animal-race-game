# 02. 아키텍처 의사결정 기록 (Architecture Decision Records - ADR)

## ADR-001: 100% 클라이언트 사이드 단일 페이지 웹앱 (Zero-Backend)
- **상태**: 승인 및 구현 완료
- **맥락**: 사내 팀원들이 슬랙이나 사내 메신저에서 URL 클릭 한 번으로 서버 설치/로그인/비용 없이 즉시 실행할 수 있어야 함.
- **결정**: GitHub Pages 및 정적 웹 호스팅에서 구동되는 순수 HTML5 / Vanilla CSS / ES Modules 아키텍처 채택.
- **결과**: 서버 유지비 0원, 0.1초 로딩 속도 달성, 오프라인 환경에서도 100% 정상 작동.

## ADR-002: Canvas 2D 기반 다중 레인 렌더러 채택 (DOM 애니메이션 배제)
- **상태**: 승인 및 구현 완료
- **맥락**: 최대 12마리의 말, 실시간 파티클, 투사체, 장애물이 동시에 움직일 때 DOM 엘리먼트 방식은 리플로우(Reflow) 및 프레임 드랍이 발생함.
- **결정**: HTML5 Canvas 2D 컨텍스트 기반의 단일 캔버스 60FPS 렌더링 파이프라인 구축.
- **결과**: 저사양 모바일/노트북에서도 60FPS 고정 유지, 캔버스 스케일링으로 반응형 해상도 완벽 지원.

## ADR-003: Web Audio API 기반 순수 오디오 신디사이저 탑재 (MP3 배제)
- **상태**: 승인 및 구현 완료
- **맥락**: 외부 MP3 에셋 로딩 실패, CORS 이슈, 대역폭 낭비 방지 필요.
- **결정**: 브라우저 내장 Web Audio API (`AudioContext`, `OscillatorNode`, `GainNode`, `BiquadFilterNode`)를 활용하여 출발 총성, 말발굽 리듬, 부스터 화염음, 팡파르를 실시간 코드 합성.
- **결과**: 외부 네트워크 의존성 0%, 0ms 재생 지연, 완전한 음소거 토글 지원.

## ADR-004: 온디바이스 AI 듀얼 엔진 구조 (Chrome Gemini Nano + 로컬 휴리스틱)
- **상태**: 승인 및 구현 완료
- **맥락**: OpenAI 등 외부 유료 API 키 입력 없이 무료로 똑똑한 텍스트 생성과 개별 말 AI 의사결정을 수행해야 함.
- **결정**:
  1. 최신 Chrome의 `window.ai` (Gemini Nano)를 1순위로 감지하여 호출.
  2. 미지원 브라우저(Safari, Firefox, 구버전 Chrome)에서는 브라우저 내장 의미론적 조합 생성형 엔진(Semantic Combinatorial Generative Engine)으로 0ms 지연 자동 폴백.
- **결과**: 어떤 브라우저에서도 오류 없이 즉시 고품질 한국어 별명, 중계, 기사 생성.

## ADR-005: 다중 레인(Multi-Lane) 아이템 물리 타겟팅 보정
- **상태**: 승인 및 수정 완료
- **맥락**: 경마 트랙은 말이 서로 다른 고유 레인(0~11)에서 달림. 던진 말의 레인 뒤에 바나나를 깔면 후속 주자가 아무도 밟지 못하는 물리적 결함 발생.
- **결정**:
  - 바나나 투척 시 자신을 뒤쫓는 2위/3위 추격자의 레인을 즉시 계산하여 그들의 진행 방향 전방 35m에 직접 매설.
  - 미사일은 발사 레인(`fromLane`)에서 1위 목표 레인(`targetLane`)으로 포물선을 그리며 유도 비행.
- **결과**: 아이템전의 박진감과 역전 드라마가 완벽하게 발생하도록 해결.

## ADR-006: 비즈니스 로직과 뷰의 순수 모듈화 및 네이티브 테스트 러택 채택
- **상태**: 승인 및 구현 완료
- **맥락**: 코드 수정 시 핵심 게임 룰(벌칙, 아이템 충돌, 순위 계산, 시드 결정론, 통계 집계)이 망가지지 않도록 자동 검증 체계 필요. 무거운 Jest/Mocha 대신 가벼운 도구 요구.
- **결정**: Node.js 내장 `node:test` 및 ES Module을 사용하여 `penalty.js`, `itemManager.js`, `presetManager.js`, `aiEngine.js`, `raceEngine.js`, `rng.js`, `statsManager.js`에 대한 40개 단위 테스트 구축.
- **결과**: `npm test` 한 번으로 100ms 이내에 100% 테스트 검증 완료.

## ADR-007: 결정론적 시드(Seeded PRNG) 및 고정 타임스텝 물리 엔진 + 스탯 공정성 모드
- **상태**: 승인 및 구현 완료 (v2.0)
- **맥락**: 실제 사내 커피 내기에서 ① 참가자마다 초기 스탯이 달라 불공정하다는 이의 제기와 ② 화면 주사율(60Hz vs 120Hz)이나 PC 성능에 따라 결과가 달라지지 않고 동일 시드 코드 입력 시 결과를 100% 재현/검증할 수 있어야 한다는 요구 발생.
- **결정**:
  1. Mulberry32 알고리즘 기반 `createRng(seed)`를 도입하여 `Math.random()`을 시뮬레이션 루프에서 제거하고 모든 스탯/아이템/날씨/물리 지터를 시드 기반으로 통일.
  2. 프레임 시간(`dt`)을 `FIXED_STEP = 1 / 60` 단위로 고정 분할 실행하여 주사율과 무관한 100% 결정론적 결과 보장.
  3. 모든 말의 5대 능력치를 `70`으로 통일하는 **공정 추첨 모드(`statMode: 'fair'`)**를 기본값으로 제공하고, 기존 350pt 분배 방식을 **능력치 전략 모드(`statMode: 'stats'`)**로 선택 가능하게 분리.
- **결과**: 동일 참가자·룰·시드 코드 공유 시 어느 브라우저에서도 동일한 1위와 결제자가 재현되어 내기 공정성 완벽 확보.

## ADR-008: 감열지 영수증 PNG 익스포터 및 사내 명예의 전당(Coffee Ledger) 도입
- **상태**: 승인 및 구현 완료 (v2.0)
- **맥락**: 경기 종료 후 슬랙/단톡방에 텍스트뿐 아니라 시각적인 인증샷을 공유하고, 누적 누가 가장 많이 커피를 샀는지 기록하고 싶다는 사용자 피드백 반영.
- **결정**:
  1. 외부 라이브러리(html2canvas 등) 없이 순수 Canvas 2D API로 지그재그 절취선, 참가자별 주문 메뉴集計, 결제자 서명란, 바코드를 그린 고해상도 PNG 익스포터(`receiptExporter.js`) 구현.
  2. `localStorage` 기반 `statsManager.js`로 누적 판수, 총 커피 잔수, 누적 금액, 최다 결제 호구왕 및 무임승차 칼퇴왕 리더보드를 자동 집계.
- **결과**: 외부 의존성 0%를 유지하면서도 사내 메신저 공유 바이럴 효과와 다회차 플레이 리텐션 극대화.
